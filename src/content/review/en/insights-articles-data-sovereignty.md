# Data sovereignty: what organizations should know

Data sovereignty goes beyond server location to include responsibilities, processing paths and information access.

## Map the data lifecycle

Identify information entering the system, where it is stored, how it moves to other services, and where backups and logs reside. Processing locations may differ from the primary server location.

## Understand responsibilities

Distinguish the party determining processing purposes from a provider processing data under agreement. Review contracts, subprocessors, transfer, retrieval and deletion terms.

## Define access controls

Identify who can access data and how permissions are granted and reviewed. Specify encryption, key management, retention and incident response requirements.

## Compare deployment options

Compare cloud, private hosting and on-premises deployment based on operational needs, security, costs and skills, not server location alone. Legal requirements vary by sector and data; consult specialists before deciding.
